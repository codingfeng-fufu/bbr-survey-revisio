## 3. 具体执行方法

### L01 机器及版本清单

**对应审稿意见：** R3-4；支撑R2-3。


1. 记录操作系统、内核、CPU、内存、虚拟化方式和可用权限，确认可以独占测试资源。
2. 为v1/v2/v3建立代码来源、完整commit、补丁及构建配置表；实际注册名字不一定是bbr1/bbr2/bbr3，必须核查。
3. 记录iperf3、iproute2及采集工具版本。检查命令帮助和实际输出字段，不照搬未经验证的命令。
4. 如果切换实现需重启，安排版本分块；不同内核的可比性问题交冯宗林，必要时补CUBIC控制组。

验收：目标实现可识别且可运行；不可用版本明确标阻塞。交付`environment.md`及命令输出。

### L02 搭建共享瓶颈

**对应审稿意见：** R3-4；R1-M4。


拓扑：S1、S2通过独立传播延迟路径汇聚到R1，经唯一前向瓶颈到R2，再到D1、D2。候选平台为Linux namespace/veth及流量控制，具体实现需试跑。

1. 建立隔离命名空间、接口、地址和路由，统一MTU与卸载设置。
2. 前向共享瓶颈设100 Mbps，其他链路容量至少为其10倍；ACK反向不施加同样瓶颈。
3. 分开配置传播时延与FIFO瓶颈队列，记录qdisc层级、限速突发量和队列上限。
4. 对称配置正反向传播延迟，使总RTT达到20/40/80 ms；不能每一方向都配置成完整目标RTT。
5. 100 Mbps、参考RTT20 ms的BDP为250,000字节；E1/E2使用固定参考BDP，Q分别为125,000、500,000、2,500,000字节。包数实现需记录换算和取整。
6. 单流试跑测实际无负载RTT、容量、CPU、队列丢包。延迟仿真器不能形成第二个隐藏瓶颈。
7. 保存创建、检查与清理脚本，清理只作用于本项目资源。

验收：测量与目标配置一致或偏差已解释；配置可重新建立；没有意外路径或资源瓶颈。

### L03 运行与采集流程

**对应审稿意见：** R3-4。


单次目录包含config.json、environment.txt、各流iperf3 JSON、tcp_state.log、queue_stats.log、runtime.log及validity.json。所有记录使用run_id和时间戳关联。

执行顺序：读取配置 → 检查实际版本/队列/ECN → 测基线 → 开服务及采集 → 启动竞争流 → 保存退出状态 → 核对文件 → 清理。记录实际启动偏差，不能只假定同时启动。

候选设置：运行180秒、预热30秒、分析30–180秒；每格5次独立重建连接。TCP/队列采样从200 ms试起并评估开销。JSON字段、接收端有效吞吐口径和采样命令以安装版本实测为准。

失败条件包含连接失败、配置不符、日志缺失或测量资源异常。低吞吐和不支持假设不算失败；任何重跑保留旧日志。

验收：一轮试跑可形成完整且可解析目录，采集不明显扰动实验；没有把未观测的内部BBR状态当作实测数据。

### L04 试跑和冻结

**对应审稿意见：** R3-4；支撑R1-M1、M2及R2-2。


1. 覆盖短/长RTT、小/大队列及计划用到的各版本，检查协议状态和采集完整性。
2. 向冯宗林报告稳态窗口是否足够、独立重复波动、CPU占用及不可比项。
3. 冻结运行时长、重复数、随机种子、配置顺序、失败判据及统计口径。
4. 保存试跑与正式运行的分离目录；正式矩阵每行包括experiment_id、协议commit、C、每流RTT、队列、流数、ECN、丢包设置和重复号。

验收：矩阵无关键空项，冯宗林确认后才能开始正式运行。

### L05 E1扩展运行：90次

**对应审稿意见：** R1-M1；支撑R1-M4。


你负责Q/BDP_ref=0.5和10两个缓冲区水平；每个水平运行BBRv1/v2/v3 × RTT2=20/40/80 ms，RTT1固定20 ms，共18配置，每格5次。其他条件：100 Mbps、2条同版本长流、FIFO、关闭ECN、不注入随机丢包。

冯宗林负责Q=2的45次，你不重复覆盖。运行顺序随机化；受内核重启限制时记录分块顺序。

每批结束检查：有效次数、实际协议、RTT、队列、每流吞吐、失败原因。不要等90次全部结束才发现采集错误。

验收：18格各有5次有效数据才能通过原范围验收；缺格登记阻塞，不能因写了说明就算完成。缩减范围由冯宗林记录并重算次数；与冯宗林核心组单位、窗口和日志结构一致。

### L06 E2扩展运行：30次

**对应审稿意见：** R1-M2；R2-3。


你负责Q=0.5和10两个水平，每格一条目标BBR流与一条CUBIC流竞争，两流RTT均为20 ms；3个BBR版本×2个队列×5次，共30次。其他条件与E1相同。

检查实际ECN协商与队列标记状态。E1等RTT结果可作为同协议对照，不重复运行。不同内核若增加CUBIC/CUBIC组，另登记预算。

验收：6格完整且ECN状态有证据；不把性能相似/不同直接解释为特定内部机制是否存在。

### L07 E3留出运行：40次

**对应审稿意见：** R1-M3、M4；R2-2；R3-3。


你负责200 Mbps的留出条件：同质RTT=10或60 ms × 队列=1或4倍各条件BDP，4个网络条件；每个分别运行BBRv3和CUBIC，每组2条同协议流，5次重复，共40次。冯宗林负责50 Mbps组。

计算口径：这里使用各配置C×RTT/8确定BDP，区别于E1/E2固定参考RTT的队列定义。200 Mbps下，10 ms对应250,000字节BDP，60 ms对应1,500,000字节BDP；队列乘以1或4。

运行前确认冯宗林已保存规则与预测。若E1/E2后修改规则，须在10/5结束前保存更新版本及E3预测，10/6才开始留出运行；来不及则顺延，不先看E3结果再补预测。发现异常只按失败判据处理，负结果保留。

丢包来源补测和阈值敏感性不是上述40次的一部分，需冯宗林另行冻结分工后实施。

验收：8个算法配置各5次；预测早于观测；不能声称这组覆盖v1/v2或真实LEO网络。

### L08 汇总与独立复跑

**对应审稿意见：** R3-4；R2-2。


1. 检查run_id唯一、文件完整、配置与实际环境一致；生成缺失/失败清单。
2. 从接收端计算每流稳态有效吞吐，并整理RTT、重传和队列指标；比例写明分母。
3. 每运行一行输出run_metrics.csv，每配置一行输出condition_summary.csv；每秒采样不算独立样本。
4. 从冯宗林亲自完成的实验选一个核心配置，独立按说明复跑，使用预先约定的比较标准解释差异。
5. 核对公平性计算所用流集合和窗口一致；图表中散点数量等于有效重复数。E1统一计算流2份额，20/20 ms基线不叫长RTT流；总吞吐为0时份额及Jain指数标为未定义并单独分析。

验收：汇总可从原始日志重新生成；没有手工替换数据；复跑有记录和解释。

### L09 复现说明和回复材料

**对应审稿意见：** R3-4；支撑R3-3。


README写清依赖、构建、拓扑、配置入口、实际成功的创建/运行/采集/清理命令、预期产物、分析步骤及已知限制。附一份最小复现示例。不能只交伪代码或“运行脚本即可”。

方法段包括版本、场景、运行时长、预热、重复、统计、失败处理。为R3-4起草回复，为相关技术意见提供实验定位。

验收：冯宗林能按说明定位并启动一个配置；所有参数与日志一致。

### L10 实验材料交付前自检

**对应审稿意见：** 内部质量检查；复核R3-4及实验对应意见。


检查稿件、图、补充材料和回复中的运行次数、版本、RTT、队列、单位及结果数字；核对未测试范围有明确说明。

验收：所有表述可以追溯到配置和汇总，未知项不写成完成项。

## 5. 第一轮开工、配置字段与运行交接

### 5.1 第一轮先做什么

1. 先交environment.md：有哪些机器、实际内核、可运行哪些协议、是否可独占。没有可运行版本先报阻塞，不下载一堆不同实现直接开跑。
2. 再交一条最小测试的完整目录，证明创建拓扑、启动流、采集日志、解析数据和清理都能工作。
3. 然后交pilot_report.md与候选矩阵；经冯宗林冻结后才生成正式run_id。
4. 正式运行每完成一个配置的5次重复就检查一次，向冯宗林交付该配置完整目录及有效性结论。

### 5.2 每次配置不得缺失的字段

| 类型 | 必填字段 |
|---|---|
| 身份 | run_id、experiment_id、配置版本、重复号、执行人、日期、机器ID |
| 实现 | 内核版本、BBR代码commit、每流实际算法名称、工具版本 |
| 网络 | C_Mbps、rtt1_ms、rtt2_ms、queue_bytes或queue_packets、包数换算假设、MTU、qdisc层级 |
| 条件 | 流数、ECN设置与实际状态、随机丢包概率/位置/种子、卸载设置 |
| 运行 | duration_s、warmup_s、analysis_start/end、采样间隔、实际启动偏差 |
| 追溯 | 原始日志路径、命令记录、退出码、有效性状态、失败理由、替代运行ID |

举例：E1_v3_Q0p5_R20-80_rep03是可采用的命名结构，表示E1、固定v3实现、Q=0.5×参考BDP、20/80 ms双流、第3次重复。这个名字不能替代config里完整commit。重跑另加attempt编号，不能覆盖rep03旧目录。

### 5.3 试跑结束必须填实的质量门槛

以下不是默认已通过的条件。L04必须给出数值、依据和冯宗林确认记录，未填实不能启动正式批量运行。

| 门槛 | 怎么确定 | 不通过怎么办 |
|---|---|---|
| 无负载RTT允许偏差（ms或%） | 重复测量基线抖动并比较配置值 | 排查延迟路径/调度后重新预检 |
| 容量/限速允许偏差 | 用单流基准及队列/字节计数解释协议开销 | 排查额外瓶颈，不通过改结果掩盖 |
| 两流启动偏差（ms） | 根据试跑实际启动控制能力确定 | 修正同步启动；超出阈值按预定规则处理 |
| 采集开销上限 | 有/无采集的试跑对比及CPU记录 | 降低采样频率并统一重做试跑 |
| 日志缺失允许范围 | 明确核心字段和统计窗口覆盖要求 | 核心日志缺失判失败，保留记录重跑 |
| 稳态及窗口规则 | 看试跑时序，固定适用全部比较组的规则 | 延长统一时长或保留动态分析 |

### 5.4 E3结果隔离与独立复跑边界

E3正式结果在预测文件保存前不得用于修改规则。你先接收配置和已冻结预测版本，再运行、交出原始结果；不替冯宗林根据结果补写预测。独立复跑属于额外质量检查，不计入你负责的160次基础运行；其他诊断、丢包补测和重跑也另列次数与时间。

### 5.5 每批交付要求

交付run_manifest.csv，逐行写run_id、配置、状态、有效性理由、文件目录；附“计划配置数/已完成配置数/有效次数/失败次数/剩余事项”。先交原始数据和可重生成汇总，再交结论草稿。只有汇总图而无日志、只有算法名字而无代码身份、重复运行被覆盖、未冻结即改参数，均需返工。

**可选补测分工**：若F09决定开展独立丢包补测，刘馨月负责CUBIC在0和0.1%两个丢包水平的10次运行；冯宗林负责BBRv3的10次。阈值敏感性实验由冯宗林负责选点、运行和分析，未另行明确分配前不计入刘馨月任务。复跑和失败重跑另计。
