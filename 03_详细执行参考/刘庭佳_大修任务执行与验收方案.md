## 3. 具体执行方案

### T01 建立图表与文字问题台账

**对应审稿意见：** R1-m1、m2、m3；R1-M1；R2-3、4。


1. 从LaTeX确认图号与图片文件的真实对应关系，不依据文件名猜测Figures 2–6。
2. 每图记录：图号、源文件、图注、正文引用、图片类型（示意/实验/文献整理）、来源、当前问题。
3. 标记Figure 2的延迟标签、Figures 5–6的RTT公平性推理及版本图中的参数问题，交冯宗林确认技术更正。
4. 搜索审稿人点名的修辞及绝对化词句，建立“原句—位置—建议”表。
5. 找摘要、框架、场景矩阵、公平性和结论的重复段落，建议保留主位置并用交叉引用替代重复。

交付：`figure_inventory.csv`、`editorial_issues.md`。

验收：每个图号可追溯到文件和正文；文字问题可定位，不擅自删掉关键限定条件。

### T02 收集制图与AI使用事实

**对应审稿意见：** R2-4。


1. 向原制图者确认具体工具、使用日期/版本（可得时）、操作用途及生成/修改范围。
2. 分开记录翻译、文字润色、布局辅助、直接生成图像、后期修改和人工重绘。
3. 对未知过程填“待确认”，不能依据图片风格推断是否使用AI。
4. 记录技术内容由谁、依据什么资料复核。
5. 原图与修订图分开记录。重绘后仍保留原图制作历史，回复审稿人时据实解释。

交付：`figure_provenance.csv`，包含图号、制作人、工具、用途、范围、人工核验依据和不确定项。

验收：每个相关图有事实记录；未知项未被写成确定事实；冯宗林确认披露事实基础。

### T03 准备可编辑草图

**对应审稿意见：** R1-M1、m3；R2-3、4。


1. 依据冯宗林提供的机制说明绘制框、箭头和标签，先不加入未经核实的公式与参数。
2. 对关键图附“本图表达的命题”及每个关键箭头的含义。
3. 将待确认的机制以问题清单交冯宗林，避免在图片内静默补全。
4. 同步准备图例、颜色、字体与术语规范，使最终重绘可快速完成。

验收：图源可编辑；技术未确认项被列出；草图状态明确，不能冒充最终图。

### T04 正式重绘技术图

**对应审稿意见：** R1-M1、m3；R2-3、4。


1. 接收冯宗林验收的版本机制表、框架说明和公平性解释，记录版本。
2. 逐项替换旧标签、箭头和不成立的推理；区分传播时延与排队时延。
3. 统一符号、单位、大小写和条件说明；机制图须注明适用版本。
4. 用可编辑绘图工具或可重生成的代码绘制，保留源文件与导出命令/设置。
5. 交冯宗林逐图签收；返工后重新导出并检查正文引用。

交付：图源、最终导出图、逐图技术核查表。

验收：不存在旧结论残留；图片与冻结说明一致；字体在论文最终尺寸下可读；冯宗林技术签收后才合入。

### T05 实验图和图注

**对应审稿意见：** 支撑R1-M1、R2-2及R3-4（实验图交付）。


1. 接收已验收的数据和分析脚本，核对run_id及输入文件版本。
2. 仅调整颜色、字体、排版和标注；改变聚合、过滤、坐标变换时必须由冯宗林确认。
3. 保留单位、图例、样本数、误差条定义和关键条件；区分单次时序与跨运行汇总。
4. 图注说明协议版本、参数条件、统计口径和数据来源，避免只写“性能比较”。
5. 如重新导出，确认与原分析数值相同；禁止手动移动数据点。

验收：图形能追溯到分析输出；颜色不承担唯一辨识信息；小尺寸和灰度下可读；刘馨月核数，冯宗林核结论。

### T06 编辑摘要、术语与重复

**对应审稿意见：** R3-1；R1-m1、m2。


1. 在正文结果冻结后，按动机、问题、方法、主要发现和贡献重写摘要。
2. 按审稿意见去除摘要中的文献引用，减少数字堆叠；仅保留有必要且被正文支持的结果。
3. 将修辞性和绝对化表达改为科学表述；不能把“在某条件下”删成普遍结论。
4. 全文统一BDP口径、版本名、延迟术语、指标缩写和表格等级名称。
5. 删除重复时保留主要论证、来源和限制，将删改建议交冯宗林合并。

交付：摘要草稿、术语表、编辑修改记录。

验收：摘要与正文一致；无新增未验证主张；审稿人点名措辞已处理；所有重大删改可追踪。

### T07 声明和回复

**对应审稿意见：** R2-4；R1-m1、m2、m3；R3-1。


1. 根据T02写AI使用声明初稿，分别描述工具、用途、范围和人工技术核验。
2. 图注与声明相互一致；涉及当前期刊要求的细节交徐守正核实，不自行声称已经满足。
3. 为R2-4、R1-m1/m2/m3及R3-1写回复草稿，提供实际修改位置。

验收：事实准确，原图和重绘过程不混淆；正文、图注和回复一致；冯宗林签收。

### T08 编译及视觉自检（终审前交付）

**对应审稿意见：** 内部排版检查；复核R1-m1、m2、m3及R3-1。


1. 从完整源码生成PDF，保存编译命令、工具版本和日志。
2. 检查缺图、未定义引用、图号错位、表格溢出、字体过小、符号缺失、截断及空白页。
3. 按最终论文尺寸逐页看图表，不仅放大到屏幕检查。
4. 逐条记录问题、修复文件、重编译结果；文档最后变动后再检查受影响页面。

验收：无影响阅读的版面错误；图文引用正确；最终PDF与冻结源码对应。

## 5. 开工材料、逐图交付包与检查表

### 5.1 第一轮先做什么

1. 拿原稿LaTeX和图片目录逐图核对，先完成figure_inventory.csv；暂时不要重绘尚未得到冯宗林确认的机制。
2. 给每张图分配稳定figure_id，并同时记录“原稿图号、修订图号、LaTeX label、文件路径”，以后编号变化仍能追踪。
3. 提交技术疑问清单与文字重复清单；可先做版式模板和不含未核实结论的草图。
4. 收到冻结技术说明或数据后再制作正式图，并把输入版本写在图源记录里。

### 5.2 每张图必须交一个完整包

| 文件 | 必须写明/包含 |
|---|---|
| 可编辑图源或生成脚本 | 节点、文字、箭头可改；实验图可由数据重生成 |
| 论文用导出图 | 与图源内容一致，分辨率/格式按最终投稿要求核实 |
| caption.md | 图意、变量/单位、适用版本、场景、来源；实验图另写重复数和误差含义 |
| provenance.md | 原图/新图制作人、工具和用途、技术依据、AI参与事实、输入版本 |
| figure_check.md | 下表逐项结论、问题修复及冯宗林签收 |

这些是每图应具备的内容，可以按figure_id集中在同一表管理，不强制大量重复文件。只交PNG或截图、不给源文件和图注，属于不完整交付。

摘要每个发现旁附正文支撑位置供内部核查，最终合稿时移除这些内部注记。编辑表使用“原文位置/原句/建议句/修改理由/是否涉及技术含义/冯宗林处理结果”。去重复时注明保留论证的目标段落；不得直接删掉实验限制或来源说明。
