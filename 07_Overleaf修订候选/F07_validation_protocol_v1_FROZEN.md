# F07：三维框架验证协议 v1（冻结）

冻结日期：2026-09-28。适用对象：候选论文中的三维框架与后续实验/外部证据整理。

## 1. 框架输入

每个案例必须记录：瓶颈容量、参考RTT、每流RTT、绝对缓冲区、缓冲区/参考BDP、丢包来源、ECN状态、BBR版本、队列管理和流数量。异构RTT案例不能只记录一个笼统BDP。

## 2. 框架输出

分别评估：

1. 吞吐：相对指定基线的有效吞吐或吞吐份额；
2. 时延：RTT中位数、p95或排队时延代理；
3. 公平性：Jain指数与每流绝对吞吐同时报告；
4. 重传：窗口内重传计数或有可靠分母的重传率。

任一输入或指标证据不足时输出 `undetermined`。不把四项指标强行合成一个分数。

## 3. working bins

- 缓冲区：shallow `<1.5×BDP`，medium `1.5–10×BDP`，deep `>10×BDP`。
- BDP：low `<1 MB`，medium `1–10 MB`，high `>10 MB`。

这些是证据整理用的 working bins，不是所有网络的物理阈值。边界附近案例必须保留绝对值和敏感性说明。

## 4. 构建材料与验证材料

构建材料：用于提出working bins、指标定义和条件性规则的原始机制资料及综述证据。验证材料：在规则冻结后选择的留出实验配置或未参与规则制定的外部数据。若E1/E2结果被用于修改规则，不能再把原E1/E2结果称为该版本规则的独立验证。

## 5. 验证判定

每个案例在查看结果前填写预测。结果分类：

- `support`：观测方向/区间落在预先登记的容差内；
- `contradict`：观测明确落在预设方向相反的一侧；
- `undetermined`：数据缺失、噪声过大或指标不适用；
- `not_applicable`：案例不满足该规则的输入条件。

容差由试跑波动、指标单位和实际意义共同确定；禁止看完正式结果后再选容差。报告预测覆盖率和所有反例。

## 6. 当前外部一致性检查

Scholz等数据只能标为 `external consistency check`：它用于检查是否存在明显矛盾，不能被写成严格的留出预测验证，因为当前工作没有证明这些数据完全未参与规则形成。

## 7. 冻结记录

规则版本：F07-v1。预测文件：`F07_predictions_TO_FILL.csv`。修改规则必须创建F07-v2，保留v1预测及验证结果，并在正文局限中说明变化。
